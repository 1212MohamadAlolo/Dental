# قواعد الامتحان والتصحيح — عقد المرحلة الثانية

## أهداف لا مجرد أرقام أسئلة

وحدة القياس هي objectiveId. الاختيار والإجابة المكتوبة للهدف ذاته عائلة دلالية واحدة. المحاولة لا تكرر الهدف ليبدو البنك أكبر. خلط الخيارات لا ينشئ حقيقة جديدة؛ يدور المحرك بين الأهداف وصيغها مع تخفيض الأولوية للمستخدمة مؤخرًا.

### امتحان درس

كل درس متاح بلا متطلبات مسبقة. الاختيار يقتصر على الأهداف المسندة إليه. افتراضيًا تشمل الجولة جميع أهدافه المتاحة مرة واحدة؛ يمكن تقسيمها إلى صفحات في الواجهة دون تغيير سؤال الجولة عند العودة. درس بلا هدف قابل للتصحيح يبقى قابلًا لفتح قراءة المصدر مع سبب التعليق، ولا يولّد المحرك سؤالًا وهميًا أو يستعير أهدافًا من وحدة أخرى.

### الامتحان الشامل

الافتراضي 34 هدفًا، مع ضمان هدف واحد على الأقل لكل وحدة من الـ17، ثم أولوية إضافية للأخطاء حتى 35% من عدد المواضع. تُضبط حصة الوحدة في هذه الأولوية كي لا تبتلع بقية المنهج. ملء المواضع الباقية يوازن عدد الأسئلة بين الوحدات ويقدم الأهداف الأقل تعرضًا. نسبة 35% تعني مواضع ذات أولوية إضافية؛ قد توجد أسئلة أخطأ بها المستخدم داخل الحصة العامة أيضًا.

يمكن اختيار 181 هدفًا لتغطية جميع الأهداف المؤلفة، ولا يعني ذلك اعتماد تغطية كل تفاصيل المصدر. طلب أقل من 17 سؤالًا ينتج جولة مختصرة مع تحذير واضح بأنها لا تمثل جميع الوحدات. لا وعد بتشكيلة لم تظهر مطلقًا إلى الأبد؛ عدد الأهداف محدود. تُمنع إعادة تسلسل الجولة السابقة نفسه متى توفر أكثر من سؤال.

التدريب يعرض التصحيح فورًا. وضع exam يؤجل واجهة التغذية الراجعة إلى finish. بيانات الإجابات موجودة محليًا بطبيعة الموقع، فلا يقدم هذا النظام ضمان منع غش أو امتحانًا رسميًا مؤمنًا.

### أخطائي

الخطأ يفتح سجلًا للهدف، لا لرقم السؤال وحده. الجولة تأخذ الأهداف ذات open=true وتفضل صيغة أخرى متاحة. الإجابة بعد كشف الحل أو بتلميح لا تمنح دليل إتقان. إعادة ضغط الزر لا تضاعف الخطأ أو الدرجة.

إغلاق الخطأ يحتاج دليلًا موضوعيًا مستقلًا: نجاحان بصيغتين مختلفتين تفصل بينهما 24 ساعة على الأقل، أو ثلاثة نجاحات متباعدة عند توفر صيغة موضوعية واحدة. أول نجاح بعد الخطأ يجب أن يتأخر 24 ساعة أيضًا. أي خطأ لاحق يعيد فتح الهدف ويمحو أدلة التعافي السابقة. اليوم يُحسب بتوقيت Europe/Berlin، والفاصل الزمني يمنع التحايل بتجاوز منتصف الليل مباشرة.

### الكتابة

تُقبل الإجابات القصيرة المطابقة للنص أو المرادفات المسجلة فقط، بعد توحيد التشكيل والهمزات والأرقام العربية. لا نزيل النفي، ولا ندمج 0.5 و5، ولا نتجاهل الوحدات أو حدود المدى. لا يكفي وجود كلمة صحيحة ضمن جملة منفية.

الإجابة غير المعروفة هي needs-review وليست خاطئة آليًا. التفسير الطويل يعرض نموذجًا ومعيار مراجعة؛ لا تمنح موافقة المستخدم على إجابته نجاحًا موضوعيًا. يمكن لـ reviewWritten تسجيل أنها خاطئة أو غير مؤكدة وإرسال الهدف للمراجعة دون تحويل التقييم الذاتي إلى درجة رسمية.

النسبة المعروضة تخص الإجابات المصححة موضوعيًا فقط؛ يجب إظهار pending وunanswered بجوارها. لا تعرض 100% إتقان للدرس عندما بقيت إجابات أو أهداف معلّقة.

## واجهة البرمجة

```js
const state = AssessmentEngine.load(localStorage).state;
const attempt = AssessmentEngine.start(AssessmentBank, state, {
  mode: 'lesson', // comprehensive | mistakes
  lessonId: 'page-07-lesson-03',
  feedback: 'training' // exam
});
// احتفظ بـ attempt.items كما هي؛ الخيارات تحمل IDs مستقلة عن ترتيب العرض.
const answer = AssessmentEngine.submit(state, questionId, response, {hint:false});
AssessmentEngine.save(localStorage, state);
const feedback = AssessmentEngine.publicFeedback(attempt, questionId);
const summary = AssessmentEngine.finish(state);
AssessmentEngine.save(localStorage, state);
```

استجابة choice هي option.id، وshort-answer نص كامل، وordering مصفوفة IDs، وmatching قاموس leftId إلى rightId. لا يبدأ start محاولة أخرى فوق جلسة غير منتهية؛ يجب الاستئناف أو إنهاء الحالية صراحةً. مفتاح التخزين الجديد `dental-assessment-v2` مستقل عن المفاتيح القديمة. الحفظ والفشل والاستيراد الرسمي للبيانات مسؤوليات الواجهة في المرحلة الثانية؛ load يعيد تحذيرًا ويحافظ على البيانات التالفة الأصلية دون حذفها.
